# 知识库与知识图谱架构设计

## 1. 模块概述

知识库管理模块是系统的知识中枢，采用 **"树形知识库为主、知识图谱为辅、RAG 检索增强"** 的三位一体设计。

- **树形知识库**：类似 AIFlowy 的文档树管理体验，左侧树导航 + 右侧内容区
- **知识图谱**：节点间的关联探索能力，力导向图可视化
- **RAG 检索**：基于向量相似度的智能搜索 + AI 问答

知识是一种可持续发展的"资产"，梳理过去的知识体系，为新知识服务。

### 数据来源

| 来源 | 方式 | 说明 |
|------|------|------|
| 手动创建 | 用户直接在知识树中创建 | 支持 Markdown 富文本编辑 |
| 资产同步 | 从固定资产/无形资产自动同步 | 新增/编辑资产时自动生成知识条目 |
| 合同同步 | 从资产文书合同自动同步 | 新增/编辑合同时自动生成 |
| 批量导入 | 上传文件解析 | 支持 PDF/DOCX/MD/TXT/图片等 |

### 2.1 现有表：`asset_knowledge`（知识条目表）

**位置**：租户 schema（`{schema}.asset_knowledge`）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 主键 |
| asset_id | BIGINT | 关联资产ID（可为空，知识条目可不关联资产） |
| doc_source | VARCHAR(50) | 数据来源：manual/asset/hardware/intangible/document |
| knowledge_type | VARCHAR(50) | 知识类型：basic/contract/hardware/intangible |

| permission_level | VARCHAR(50) | 权限等级：public/internal/secret |
| owner_type | VARCHAR(50) | 归属类型：user/dept/role |
| owner_id | BIGINT | 归属ID |
| created_by/at/updated_by/at/deleted | - | 通用审计字段 |

### 2.2 新增表：`knowledge_tree`（知识树节点表）

**位置**：租户 schema（`{schema}.knowledge_tree`）

```sql
CREATE TABLE IF NOT EXISTS {schema}.knowledge_tree (
    id BIGINT PRIMARY KEY,
    knowledge_id BIGINT REFERENCES {schema}.asset_knowledge(id) ON DELETE CASCADE,
    parent_id BIGINT REFERENCES {schema}.knowledge_tree(id),
    node_type VARCHAR(20) NOT NULL DEFAULT 'document',  -- folder / document / link
    title VARCHAR(255) NOT NULL,                         -- 节点显示名称
    icon VARCHAR(50),                                    -- 自定义图标（如 📄 📁 🔗）
    sort_order INTEGER NOT NULL DEFAULT 0,               -- 同级排序
    is_expanded BOOLEAN NOT NULL DEFAULT true,           -- 是否展开
    created_by BIGINT,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    updated_by BIGINT,
    updated_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    deleted SMALLINT NOT NULL DEFAULT 0
);

COMMENT ON TABLE {schema}.knowledge_tree IS '知识树节点表（AIFlowy 风格树形导航）';
COMMENT ON COLUMN {schema}.knowledge_tree.knowledge_id IS '关联知识条目ID（folder 类型可为空）';
COMMENT ON COLUMN {schema}.knowledge_tree.parent_id IS '父节点ID（顶级节点为空）';
COMMENT ON COLUMN {schema}.knowledge_tree.node_type IS '节点类型：folder=文件夹 document=文档 link=链接';
COMMENT ON COLUMN {schema}.knowledge_tree.title IS '节点显示名称';
COMMENT ON COLUMN {schema}.knowledge_tree.icon IS '自定义图标';
COMMENT ON COLUMN {schema}.knowledge_tree.sort_order IS '同级排序号（越小越靠前）';
COMMENT ON COLUMN {schema}.knowledge_tree.is_expanded IS '是否展开（保存用户展开状态）';

CREATE INDEX IF NOT EXISTS idx_knowledge_tree_parent ON {schema}.knowledge_tree (parent_id);
CREATE INDEX IF NOT EXISTS idx_knowledge_tree_knowledge ON {schema}.knowledge_tree (knowledge_id);
```

### 2.3 新增表：`knowledge_relation`（知识图谱关联表）

**位置**：租户 schema（`{schema}.knowledge_relation`）

```sql
CREATE TABLE IF NOT EXISTS {schema}.knowledge_relation (
    id BIGINT PRIMARY KEY,
    source_id BIGINT NOT NULL,                            -- 源节点ID
    source_type VARCHAR(20) NOT NULL,                     -- source 类型：knowledge / asset
    target_id BIGINT NOT NULL,                            -- 目标节点ID
    target_type VARCHAR(20) NOT NULL,                     -- target 类型：knowledge / asset
    relation_type VARCHAR(50) NOT NULL,                   -- 关联类型
    relation_weight REAL NOT NULL DEFAULT 1.0,            -- 关联权重（0~1）
    auto_discovered BOOLEAN NOT NULL DEFAULT false,       -- 是否自动发现
    created_by BIGINT,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    deleted SMALLINT NOT NULL DEFAULT 0
);

COMMENT ON TABLE {schema}.knowledge_relation IS '知识图谱关联表';
COMMENT ON COLUMN {schema}.knowledge_relation.relation_type IS '关联类型：related_to/references/derived_from/belongs_to/depends_on';
COMMENT ON COLUMN {schema}.knowledge_relation.relation_weight IS '关联权重（自动发现时基于向量相似度）';
COMMENT ON COLUMN {schema}.knowledge_relation.auto_discovered IS '是否由系统自动发现（vs 手动创建）';

CREATE INDEX IF NOT EXISTS idx_knowledge_relation_source ON {schema}.knowledge_relation (source_id, source_type);
CREATE INDEX IF NOT EXISTS idx_knowledge_relation_target ON {schema}.knowledge_relation (target_id, target_type);
```

```rust
#[derive(Debug, Clone, Serialize, Deserialize, FromRow)]
pub struct KnowledgeTree {

    #[serde(serialize_with = "opt_i64_to_string")]
    pub updated_by: Option<i64>,
    pub updated_at: Option<DateTime<Utc>>,

#[derive(Debug, Clone, Serialize, Deserialize, FromRow)]

    #[serde(serialize_with = "opt_i64_to_string")]

    pub user_id: i64,
    pub message_count: i32,
    pub created_at: Option<DateTime<Utc>>,
    pub updated_at: Option<DateTime<Utc>>,

/// AI 对话消息
#[derive(Debug, Clone, Serialize, Deserialize, FromRow)]
pub struct AiChatMessage {
    #[serde(serialize_with = "i64_to_string")]
    pub id: i64,

    pub sources: Option<serde_json::Value>,  // JSONB

/// 知识树节点（前端树组件用）
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct KnowledgeTreeNode {
    pub value: String,                          // id 转字符串
    pub label: String,                          // 显示名称
    pub node_type: String,                      // folder / document / link
    pub icon: Option<String>,                   // 图标
    pub is_expanded: bool,                      // 是否展开

}

/// 知识图谱节点（前端图谱用）
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct GraphNode {
    pub id: String,
    pub label: String,
    pub node_type: String,     // knowledge / asset
    pub icon: Option<String>,
    pub color: Option<String>,
}

/// 知识图谱边
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct GraphEdge {
    pub source: String,
    pub target: String,
    pub label: String,         // 关联类型
    pub weight: f32,
}
```

## 5. 知识图谱关联类型

| 关联类型 | 说明 | 方向性 | 适用场景 |
|---------|------|--------|---------|
| `related_to` | 相关（弱关联） | 双向 | 内容相似的知识条目 |
| `references` | 引用（强关联） | 单向 | A 文档引用了 B 文档 |
| `derived_from` | 衍生自 | 单向 | A 知识从 B 知识衍生 |
| `belongs_to` | 属于 | 单向 | 知识条目属于某个分类 |
| `depends_on` | 依赖 | 单向 | A 知识的理解依赖 B 知识 |

### 自动关联推荐

基于向量相似度（`vector_data` 字段的余弦相似度），自动推荐关联节点：

```
余弦相似度 = cos(A, B) = (A · B) / (|A| * |B|)

阈值 >= 0.85 → 自动创建 related_to 关联
阈值 0.70~0.85 → 推荐给用户手动确认
阈值 < 0.70 → 不处理
```


## 9. 流程调度层：Zen Engine Skill 体系

### 9.1 设计理念

Zen Engine 不仅是流程调度引擎，更是一个 **Skill（技能）运行时平台**。每个 Skill 是一个可独立加载、可用户自定义的 AI 工作流模块，以 **Markdown 编辑器作为统一的交互界面**。

**核心思想：**
- **Skill = 输入(Markdown) → 处理(Python/LangGraph) → 输出(Markdown)**
- 用户通过 Markdown 编辑器与 Skill 交互：选中文本、右键调用、结果直接插入文档
- 用户可以自己编写 Skill（Python 脚本），系统自动发现并注册
- 类似 Obsidian 的社区插件 + ChatGPT 的对话界面 + VSCode 的命令面板三合一

### 9.3 Skill 定义规范

每个 Skill 是一个 Python 文件，放在 `skills/` 目录下，系统自动发现并注册。

```python
# skills/rag_qa.py — RAG 问答 Skill 示例

from zen_engine import Skill, SkillContext, SkillResult
from typing import Optional

class RagQaSkill(Skill):
    """基于知识库的 RAG 问答"""
    
    # === Skill 元数据 ===
    id = "rag-qa"                          # 唯一 ID
    name = "RAG 问答"                       # 显示名称
    description = "基于知识库内容回答选中文本中的问题"  # 描述
    icon = "🤖"                             # 图标
    version = "1.0.0"                      # 版本号
    author = "system"                      # 作者（用户自定义时可填用户名）
    
    # === Skill 配置 ===
    config_schema = {
        "top_k": {"type": "int", "default": 5, "description": "检索数量"},
        "min_score": {"type": "float", "default": 0.7, "description": "最低相似度"},
        "include_sources": {"type": "bool", "default": True, "description": "显示来源"},
    }
    
    def execute(self, ctx: SkillContext) -> SkillResult:
        """执行 Skill（核心逻辑）"""
        # ctx.input_text — 用户选中的 Markdown 文本
        # ctx.config — 用户配置的参数
        # ctx.knowledge_service — 知识库服务
        # ctx.llm_client — LLM 客户端
        
        question = ctx.input_text
        top_k = ctx.config.get("top_k", 5)
        
        # 1. 向量化问题
        embedding = self.embed(question)
        
        # 2. 检索知识库
        chunks = ctx.knowledge_service.search_similar(
            embedding=embedding,
            top_k=top_k,
            min_score=ctx.config.get("min_score", 0.7),
            user_id=ctx.user_id,
            tenant_id=ctx.tenant_id,
        )
        
        # 3. 构建 Prompt 调用 LLM
        answer = ctx.llm_client.chat(
            system_prompt="你是一个企业资产助手...",
            context=self._format_chunks(chunks),
            question=question,
        )
        
        # 4. 返回结果（Markdown 格式）
        return SkillResult(
            output=f"> 🤖 **RAG 查询结果**\n>\n> {answer}\n>\n" + 
                   self._format_sources(chunks) if ctx.config.get("include_sources") else "",
            output_type="markdown",        # markdown / insert / replace / append
            position="after_selection",    # after_selection / replace_selection / new_document
        )
```

```rust
// src-tauri/src/engine/skill_registry.rs

use std::collections::HashMap;
use pyo3::prelude::*;
use serde::{Serialize, Deserialize};

/// Skill 元数据
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct SkillMeta {
    pub id: String,
    pub name: String,
    pub description: String,
    pub icon: String,
    pub version: String,
    pub author: String,
    pub skill_type: SkillType,        // builtin / custom
    pub config_schema: serde_json::Value,
    pub file_path: String,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub enum SkillType {
    Builtin,
    Custom,
}

/// Skill 注册表
pub struct SkillRegistry {
    skills: HashMap<String, SkillMeta>,
    python_skills: HashMap<String, Py<PyModule>>,  // 已加载的 Python Skill 模块
}

impl SkillRegistry {
    /// 扫描并注册所有 Skill
    pub fn scan(py: Python) -> Result<Self, String> {
        let mut registry = SkillRegistry {
            skills: HashMap::new(),
            python_skills: HashMap::new(),
        };
        
        // 1. 扫描内置 Skill
        registry.scan_directory(py, "./skills/builtin")?;
        
        // 2. 扫描用户自定义 Skill
        registry.scan_directory(py, "./skills/custom")?;
        
        Ok(registry)
    }
    
    fn scan_directory(&mut self, py: Python, dir: &str) -> Result<(), String> {
        let path = std::path::Path::new(dir);
        if !path.exists() { return Ok(()); }
        
        for entry in std::fs::read_dir(path).map_err(|e| e.to_string())? {
            let entry = entry.map_err(|e| e.to_string())?;
            let file_path = entry.path();
            
            if file_path.extension().map_or(false, |ext| ext == "py") {
                // 动态导入 Python Skill 模块
                let module_name = file_path.file_stem().unwrap().to_str().unwrap();
                let module = py.import(&format!("skills.{}", module_name))
                    .map_err(|e| format!("加载 Skill {} 失败: {}", module_name, e))?;
                
                // 读取 Skill 元数据
                let skill_class = module.getattr("Skill")?;  // 约定：每个文件有 Skill 类
                let meta: SkillMeta = skill_class.getattr("meta")?.extract()?;
                
                registry.skills.insert(meta.id.clone(), meta);
                registry.python_skills.insert(module_name.to_string(), module.into());
            }
        }
        Ok(())
    }
    
    /// 获取所有 Skill 列表
    pub fn list_skills(&self) -> Vec<&SkillMeta> {
        self.skills.values().collect()
    }
    
    /// 执行 Skill
    pub fn execute(&self, py: Python, skill_id: &str, ctx: SkillContext) -> Result<String, String> {
        let module = self.python_skills.get(skill_id)
            .ok_or_else(|| format!("Skill {} 未找到", skill_id))?;
        
        let skill_class = module.getattr(py, "Skill")?;
        let instance = skill_class.call0(py)?;
        let result = instance.call_method1(py, "execute", (ctx,))?;
        result.extract::<String>(py).map_err(|e| e.to_string())
    }
}
```

```rust
// src-tauri/src/engine/skill_sandbox.rs

/// Skill 执行沙箱（安全隔离）
pub struct SkillSandbox {
    max_execution_time: Duration,    // 最大执行时间（默认 60s）
    max_output_size: usize,          // 最大输出大小（默认 1MB）
    allowed_imports: Vec<String>,    // 允许导入的 Python 模块白名单
    blocked_imports: Vec<String>,    // 禁止导入的模块黑名单
}

impl SkillSandbox {
    pub fn new() -> Self {
        SkillSandbox {
            max_execution_time: Duration::from_secs(60),
            max_output_size: 1024 * 1024,
            allowed_imports: vec![
                "zen_engine".into(),
                "langgraph".into(),
                "sentence_transformers".into(),
                "json".into(),
                "re".into(),
                "typing".into(),
            ],
            blocked_imports: vec![
                "os".into(), "subprocess".into(), "shutil".into(),
                "socket".into(), "requests".into(), "http".into(),
            ],
        }
    }
    
    /// 在沙箱中执行 Skill
    pub fn execute(&self, py: Python, module: &PyModule, ctx: SkillContext) -> Result<String, String> {
        // 1. 注入安全限制
        self.apply_restrictions(py)?;
        
        // 2. 设置超时
        let result = std::panic::catch_unwind(std::panic::AssertUnwindSafe(|| {
            // 实际执行
            let skill_class = module.getattr("Skill")?;
            let instance = skill_class.call0(py)?;
            let result = instance.call_method1(py, "execute", (ctx,))?;
            result.extract::<String>(py)
        }));
        
        // 3. 清理安全限制
        self.remove_restrictions(py)?;
        
        match result {
            Ok(Ok(output)) => {
                if output.len() > self.max_output_size {
                    return Err("Skill 输出超过大小限制".into());
                }
                Ok(output)
            }
            Ok(Err(e)) => Err(format!("Skill 执行错误: {}", e)),
            Err(_) => Err("Skill 执行超时或崩溃".into()),
        }
    }
}
```

### 9.10 关键设计原则

1. **数据库操作始终由 Rust 端执行**，Python 端只做计算密集型工作（AI 推理、文本处理）
2. **GIL 隔离**：Python 调用放在 `tokio::task::spawn_blocking` 中，避免阻塞 Tokio 异步运行时
3. **流式响应**：通过 `mpsc` 通道将 Python 生成器结果桥接到 Rust Stream，再通过 Tauri IPC 推送到前端
4. **Python 环境自包含**：随 Tauri 应用打包，不依赖用户系统 Python
5. **Skill 沙箱隔离**：限制 Python 模块导入白名单，防止恶意代码
6. **用户可扩展**：用户只需在 `skills/custom/` 目录下放一个 `.py` 文件，系统自动发现

#### 3.2 Zen Engine 流程引擎（引擎内置，非外挂）

```rust
// src-tauri/src/engine/otel_span.rs - 引擎内置 Span 生成器

pub struct NodeSpan {
    span: Span,
    start_time: Instant,
    memory_before: u64,
    memory_after: u64,
}

impl NodeSpan {
    /// 创建节点 Span（引擎自动调用，节点开发者无感）
    pub fn begin(node: &FlowNode, parent_context: &SpanContext) -> Self {
        let span = tracing::info_span!(
            "zen.node.execute",
            node_id = node.id,
            node_type = %node.node_type,
            branch_condition = tracing::field::Empty,
            retry_count = tracing::field::Empty,
        );
        let memory_before = get_current_process_memory();
        NodeSpan { span, start_time: Instant::now(), memory_before, memory_after: 0 }
    }

    /// 记录分支命中条件
    pub fn set_branch_condition(&self, condition: &str) {
        self.span.record("branch_condition", condition);
    }

    /// 结束 Span，自动记录耗时和内存增量
    pub fn end(mut self) {
        self.memory_after = get_current_process_memory();
        let duration_ms = self.start_time.elapsed().as_millis() as f64;
        let memory_delta = self.memory_after.saturating_sub(self.memory_before);
        SKILL_DURATION_HISTOGRAM.record(duration_ms, &[KeyValue::new("node_type", node_type)]);
        MEMORY_DELTA_GAUGE.record(memory_delta as f64, &[]);
        drop(self.span);
    }
}
```

```python
TOKEN_USAGE = meter.create_counter("ai.skill.token_total", description="Token 消耗总量")
GPU_MEMORY = meter.create_gauge("ai.gpu.process_memory", description="当前进程 GPU 显存占用", unit="bytes")

class BaseAISkill:
    """所有 Skill 的基类，内置 OTel 埋点，子类实现 run_logic 即可"""

    def execute(self, state: dict) -> dict:
        with tracer.start_as_current_span(self.skill_id, attributes={"skill.name": self.name}) as span:
            mem_before = psutil.Process(os.getpid()).memory_info().rss
            gpu_before = self._get_gpu_memory()
            try:
                result = self.run_logic(state)
                mem_after = psutil.Process(os.getpid()).memory_info().rss
                gpu_after = self._get_gpu_memory()
                span.set_attribute("memory.delta_bytes", mem_after - mem_before)
                span.set_attribute("gpu.memory.delta_bytes", gpu_after - gpu_before)
                duration_ms = (time.time() - start_time) * 1000
                SKILL_DURATION.record(duration_ms, {"skill": self.skill_id})
                return result
            except Exception as e:
                span.record_exception(e)
                span.set_status(Status(StatusCode.ERROR, str(e)))
                raise
```

```rust
pub async fn execute_cypher_with_trace(
    pool: &Pool, query: &str, params: HashMap<String, Value>,
) -> Result<Vec<Row>, String> {
    let span = tracing::info_span!("memgraph.query", db.system = "memgraph",
        db.statement = query, db.rows = tracing::field::Empty);
    let start = Instant::now();
    let result = pool.execute(query, params).await;
    let duration = start.elapsed().as_millis() as f64;
    span.record("db.rows", result.as_ref().map_or(0, |r| r.len()));
    CYPHER_DURATION_HISTOGRAM.record(duration, &[KeyValue::new("db.system", "memgraph")]);
    if duration > 1000.0 {
        tracing::warn!("慢查询 ({}ms): {}", duration, query);
        SLOW_QUERY_COUNTER.add(1, &[KeyValue::new("db.system", "memgraph")]);
    }
    result.map_err(|e| e.to_string())
}
```

### 四、资源观测专项设计（Python 内存 / GPU 痛点）

#### 4.1 Rust 侧全局进程资源采集器

```rust
// src-tauri/src/engine/resource_collector.rs
pub struct ResourceCollector { nvml: Option<Nvml> }

impl ResourceCollector {
    /// 每 5 秒采集一次所有 Python 进程资源
    pub async fn collect_loop(self: Arc<Self>) {
        let mut interval = tokio::time::interval(Duration::from_secs(5));
        loop {
            interval.tick().await;
            let metrics = self.collect_all().await;
            self.export_metrics(&metrics).await;
            self.check_thresholds(&metrics).await;
        }
    }

    async fn check_thresholds(&self, metrics: &ResourceSnapshot) {
        for proc in &metrics.processes {
            if proc.rss_bytes > 2 * 1024 * 1024 * 1024 {  // 2GB
                tracing::warn!("Python 进程 {} 内存超限: {:.1}GB", proc.pid, proc.rss_bytes as f64 / 1e9);
                RATE_LIMITER.set_limit(0);  // 触发降级
            }
            if proc.rss_bytes > 4 * 1024 * 1024 * 1024 {  // 4GB
                tracing::error!("Python 进程 {} 内存临界，触发重启", proc.pid);
                self.restart_python_vm().await;
            }
        }
    }
}
```
