## 1. 项目现状速览

```
assets-platform/                          pnpm + turbo monorepo
├─ apps/web/                              Next.js 16（app router，output:"export"，distDir:"dist"）
│   └─ src/utils/adapters/                自研 Tauri/HTTP 双适配器（command 名 → REST 路径手工映射表）
├─ apps/backend/src-tauri/                Tauri 2 桌面壳（同时内置 axum HTTP 服务）
│   ├─ src/commands/*.rs                  16 个命令模块，123 个 #[tauri::command]
│   └─ crates/                            assets-api(axum) / database / service / storage / engine / workflow / utils
├─ apps/doc-parser/                       Python FastAPI 多模态解析服务（PDF/图片/音频/视频 → 文本）
├─ docs/                                  设计方案文档
└─ TODO.md                                架构修复清单（部分与代码状态不符，见 §A）
```

**关键架构事实**

1. 后端**同时存在两套 API 面**：Tauri IPC 命令层（123 个命令）与 axum HTTP 层（14 个路由模块），共用 `crates/assets-service` 业务实现，但入口、参数命名（camelCase / snake_case）与错误模型各不相同。
2. 多租户采用 **PostgreSQL schema 隔离**：`public` 存全局表（`sys_user`/`sys_tenant`/`sys_role`…），每租户一个 schema；SQL 由 `schema_prefix()` 拼前缀（`crates/assets-database/src/lib.rs:72`）。
3. 前端为**纯客户端渲染 + 静态导出**（52 个 `'use client'`，根布局即客户端组件），登录守卫在前端 `useEffect`。
4. `doc-parser` 是**独立部署的多模态解析服务**（既定部署形态为"应用不自拉起，由 systemd/Docker 承载"），当前 token 供应只覆盖"应用自己拉起子进程"这一种模式 —— 见 P0-6。
5. 编译诊断现状：仅 lib target 就有**近百条警告**（大量 `non_snake_case`：`userId/tenantId/pageSize/bizType/fileSize` 等；`crates/assets-workflow/src/commands.rs:22-23` 的 unused variable `biz_type`/`biz_id`），clippy 目前不构成门禁。

### P0-6 doc-parser 鉴权与部署模式（token 供应与进程管理耦合）🟠 ✅实测

**前提**：doc-parser 的既定部署形态是**独立部署**（同机 Docker / systemd，跨机后续），即由部署方承载进程，后端只作为客户端调用。

> **v1.2 更正**：本条初版写为"独立部署下 token 永不被设置"，结论**过强**。经复核：`[doc_parser] token/url` 经 `load_env()` 的通用映射**其实是生效的**（见下方"配置链路"）。真实缺陷是：① token 供应与"是否拉起进程"**耦合**；② 来源**随运行时端口状态漂移**；③ 模式 A 下静态 token 被**随机 UUID 静默覆盖**；④ 配置面原本缺示例，导致"只配 `enabled=false` 不配 token"这类必错写法无提示。

**部署模式矩阵与 token 供应现状**

| 模式 | 场景 | token 实际来源（实测） | 结论 |
|---|---|---|---|
| A 内嵌自启动 | 应用拉起 uvicorn（`enabled=true` 且端口空闲） | `:193-194` 生成随机 UUID，**覆盖**配置值，并注入子进程 | ✅ 功能可用；⚠️ 配置的静态 token 被静默丢弃 |
| B 独立进程（systemd） | 部署方启动，应用侧 `enabled=false` | 早退分支 → 不生成 → **沿用 `load_env()` 载入的配置/环境变量** | ✅ 配了 `token` 即可用；未配则 401 |
| C 独立容器（Docker） | 部署方容器化，`PARSER_HOST=0.0.0.0` | 同 B（端口被占 → 早退） | ✅ 同 B；未配 token 且对端也未配时 → **无鉴权直通**（fail-open） |

**配置链路（为什么 `[doc_parser] token` 当前可用）**

`apps/backend/src-tauri/src/lib.rs:54-65` 的 `load_env()` 对**任意** `[section] key` 生成 `SECTION_KEY` 环境变量并 `set_var`；调用顺序为 `:92 load_env()` → `:96 start_doc_parser()` → 之后才有任何请求：

| 配置键 | 映射到的环境变量 | 当前是否生效 |
|---|---|---|
| `enabled` / `python` / `host` / `port` | `DOC_PARSER_ENABLED` / `_PYTHON` / `_HOST` / `_PORT` | ✅ 生效（仅模式 A 使用） |
| `token` / `url` | `DOC_PARSER_TOKEN` / `DOC_PARSER_URL` | ✅ **生效**（v1.1 误写为"待 B0-4a"）；⚠️ 模式 A 下会被随机 UUID 覆盖 |
| `autostart` | `DOC_PARSER_AUTOSTART` | ❌ 全仓无读取处，**不生效**（代码只认 `DOC_PARSER_ENABLED`） |
| `timeout_secs` / `health_path` | — | ❌ 不生效（客户端硬编码 600s，见 `:50`；无健康探测逻辑） |

**P0-6b 进程回收缺失 → 孤儿进程与端口占用**

`apps/backend/src-tauri/src/lib.rs:96` `let _doc_parser_child = assets_service::doc_parser::start_doc_parser();`：`Child` 句柄被丢弃，应用退出**不会**终止由它拉起的 uvicorn → 孤儿进程长期占用 8321。后果：① 下次启动必走 `:151`"端口占用"分支，token 来源切换为配置/环境变量（模式 A 未配 token 时请求 401）；② 若部署方改用自有 systemd 服务，会先撞端口冲突；③ 用户以为"应用管理着这个进程"，实际两边都不管。

**影响范围**：唯一调用方是 `crates/assets-service/src/conversation_service.rs:304`（`/chat` 附件解析，`skip_index: true`）。按现状：

- **可用写法**：`[doc_parser]` 配 `enabled=false` + `token=<与对端一致>`（经 `load_env()` 生效）；
- **必错写法**：只配 `enabled=false` 而未提供 `token`（初版配置示例缺失时最自然的写法）→ 请求不带 `X-API-Token` → 对端配了 token 则 401（功能整段不可用），对端未配则**无鉴权直通**（安全洞，Docker 形态 `PARSER_HOST=0.0.0.0` 时尤甚）；
- 因此 B0-4a 的目标不是"让 token 可用"，而是**统一供应优先级、消除随环境漂移、去掉静默覆盖**，并让 token 缺失成为**启动期显式错误**。

**评级 / 复核**：🟠 中-高｜✅ 实测（`load_env()` 映射与调用顺序、`grep 'DOC_PARSER_[A-Z_]+'` 的全部读取点、`autostart`/`timeout_secs`/`health_path` 无读取处均已实测）

| doc-parser 资源与数据位置 | Whisper/Embedding 模型缓存、嵌入式 SurrealDB 数据、抽帧临时目录在容器内均为临时层，重建即丢失/重复下载 | Docker 交付物要求挂载 `docparser-cache:/root/.cache` 与 `docparser-data:/app/data`；指南中给出显式命令 |
| 容器网络暴露风险 | 容器内必须 `PARSER_HOST=0.0.0.0`，若端口发布写成 `-p 8321:8321` 则暴露到所有网卡 | 交付物与指南**统一使用 `-p 127.0.0.1:8321:8321`**；并由 B0-4b 的启动自检强制 token 非空 |
| 假期窗口 | 10-01 ~ 10-07 假设为法定假期，B1-2/B1-3/B1-4 已按 10-08 起排 | 若实际不休假可提前 5 个工作日；若假期更长则 M1 顺延并同步 M2/M3 |
| 单人瓶颈 | B1-3、B1-4、B2-3 已标注可并行，其余为串行依赖 | 串行链 B0-2 → B2-2、B1-1 → B1-2 优先保障人力 |
| 契约自动化成本 | B2-1 需引入 DTO 生成（OpenAPI / 类型导出） | 先在 2 个模块试点，验证后再全量替换映射表 |
