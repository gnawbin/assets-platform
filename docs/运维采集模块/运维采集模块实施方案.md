## 0. 文档定位与本刀边界

### 0.1 本刀做什么

1. **远程连接能力补齐**：Docker / Swarm 的 mTLS 支持「证书 PEM 内联」（此前只支持本机证书文件路径）。
2. **接口层从 0 到 1**：`ops` crate 目前只是库 + 示例，没有任何 HTTP 路由 / Tauri 命令 / 表。本刀补齐
   `service → api → tauri command` 三层，并落 `ops_connection` 配置表。
3. **资源与台账的桥**：新增 `asset_ops_link` 中间表（方案 C），采集结果按
   `(connection_id, resource_uid)` 幂等 upsert；资源要变成资产时由人工绑定 `asset_id`。
4. **前端页面**：`/ops/connections`（连接管理）、`/ops/resources`（资源清单 + 绑定资产），
   含 `sys_menu` 菜单种子与侧边栏图标。

### 0.2 本刀不做什么

| 不做 | 归属 |
|---|---|
| 对账器自动建资产（`assets` 自动建档） | 后续迭代（需先定 `asset_no` 编码规则、`category_id` 默认分类、`asset_type=logical`） |
| 启停 / exec / 删除等写操作 | 总方案 §5，V1.2 |
| 日志拉取、AI 故障总结 | 总方案 §4，V1.1 |
| 云资产连接器（ECS/RDS/OSS） | 总方案 §11 第 5 条，V1.0 后置 |
| 采集调度常驻（cron/watch） | 后续迭代（本轮只有手动 `collect`） |
| 5 大类分类改造、状态 8 态升级 | 总方案 §2.1 / §2.3，独立任务 |

### 0.3 验收口径（DoD）

- 后端：**11 个 service 入口 = 11 条 HTTP 路由 = 11 个 Tauri 命令**，命名逐字对齐。
- 数据：`ops_connection`、`asset_ops_link` 两张表随 `init_postgres_database` 自动创建（新老租户都覆盖）。
- 安全：连接凭证仅以 AES-256-GCM 密文落库；`AuthKind` / DTO 的 `Debug` 全掩码；任何接口都不回传明文。
- 前端：两个页面可用，HTTP / Tauri 双通道都能跑（`httpAdapter` 映射齐全）。
- 验证：`cargo test -p ops --features docker,k8s`、`cargo check -p database/api/assetsplatform_lib`、
  `pnpm -C apps/web exec tsc --noEmit` 全绿。

## 1. 现状核查结论（实施前必须知道的三条硬事实）

### 1.1 `ops` crate 目前与资产台账**零关联**

- `crates/ops/Cargo.toml` 依赖里**没有** `database` / `sqlx`；crate 文档明确写「不做落库、不做调度、不做启停」。
- 全仓 `resource_uid` / `last_seen_at` **只出现在注释**（`model.rs` L422/L497/L559、`connector/mod.rs` L406），
  没有任何 SQL 或字段。
- `tenant_tables.sql` 的 `assets` 表（L31-54）无 `resource_uid` / `last_seen_at` / `source_connection_id`；
  `asset_category`（L6-18）无 `category_scope`。总方案 §2.2/§2.1 描述的是**目标态**，不是现状。

> 结论：`ResourceRecord.uid()` / `observed_at` / `ResourceStatus` / `CategoryScope::Logical` 都是「预留给对账器的钩子」，
> 本刀通过 `asset_ops_link` 承接，不去动台账表。

### 1.2 `--features k8s` 当前编不过（既有缺陷，非本刀引入）

| 证据 | 内容 |
|---|---|
| `Cargo.lock` | 同时存在 `k8s-openapi 0.27.1` 与 `0.28.0` |
| `kube-client 4.2.0/Cargo.toml` | `k8s-openapi = "0.28.0"`，`features = []` |
| `Cargo.toml`（workspace） | 写的是 `0.27.0` + `v1_32`，只给 0.27 开版本 feature |
| 实测 | `cargo test -p ops --features docker,k8s` → `k8s-openapi build.rs` panic：`None of the v1_* features are enabled` |

修复：workspace 的 `k8s-openapi` 升到 `0.28.0` 并保留 `v1_32`（0.28 支持 v1_32~v1_36；
`k8s.rs` 只用 `api::{core,apps,batch,networking}::v1` 等稳定路径，无破坏性变更）。

### 1.3 bollard 的 TLS 客户端证书是**懒加载**（决定 PEM 内联的实现方式）

`bollard 0.21` 的 `connect_with_ssl(addr, key_path, cert_path, ca_path, timeout, ver)` 只接受**路径**：
CA 在构造期预读，而客户端证书/私钥由 `DockerClientCertResolver { ssl_key: PathBuf, ssl_cert: PathBuf }`
**在每次 TLS 握手时**才从磁盘读。因此 PEM 内联必须物化成临时文件，且**生命周期必须跟随连接器**，
不能在连接后立即删除 —— 这就是 `CertMaterial` 守卫存在的原因。

## 2. 数据模型

### 2.1 `ops_connection`（采集连接配置）

```sql
CREATE TABLE IF NOT EXISTS {schema}.ops_connection (
    id BIGINT PRIMARY KEY,
    connection_name VARCHAR(100) NOT NULL,
    provider VARCHAR(32) NOT NULL,          -- docker / swarm / k8s
    endpoint VARCHAR(255) NOT NULL,         -- local:// / tcp://h:2375 / https://h:2376 / https://api:6443
    auth_type VARCHAR(32) NOT NULL,         -- AuthKind::describe() 的稳定编码
    auth_config_enc TEXT,                   -- AES-256-GCM(JSON)，无凭证的认证方式为 NULL
    credential_hint VARCHAR(255),           -- 只存“CA/证书/私钥已就绪”这类提示
    namespace VARCHAR(128),
    timeout_secs INTEGER NOT NULL DEFAULT 15,
    docker_api_version VARCHAR(16),
    max_items INTEGER NOT NULL DEFAULT 20000,
    poll_interval_secs INTEGER NOT NULL DEFAULT 300,
    enabled SMALLINT NOT NULL DEFAULT 1,
    last_collect_at TIMESTAMPTZ,
    last_error TEXT,
    created_by BIGINT, created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_by BIGINT, updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    deleted SMALLINT NOT NULL DEFAULT 0
);
CREATE UNIQUE INDEX IF NOT EXISTS uk_ops_connection_name
    ON {schema}.ops_connection(connection_name) WHERE deleted = 0;
CREATE INDEX IF NOT EXISTS idx_ops_connection_provider
    ON {schema}.ops_connection(provider) WHERE deleted = 0;
```

`auth_type` 取值即 `AuthKind::describe()`：

| auth_type | 适用 provider | 需要凭证 |
|---|---|---|
| `local_socket` | docker / swarm | 否 |
| `plain_tcp` | docker / swarm | 否 |
| `mutual_tls` | docker / swarm | 是（三个证书**路径**） |
| `mutual_tls_inline` | docker / swarm | 是（三段 **PEM 原文**） |
| `kubeconfig_file` | k8s | 否（读后端主机上的文件） |
| `kubeconfig_inline` | k8s | 是（kubeconfig YAML 原文） |
| `direct` | k8s | 是（SA Token 或客户端证书对） |

### 2.2 `asset_ops_link`（采集资源 ↔ 台账桥表）

```sql
CREATE TABLE IF NOT EXISTS {schema}.asset_ops_link (
    id BIGINT PRIMARY KEY,
    connection_id BIGINT NOT NULL,
    provider VARCHAR(32) NOT NULL,
    resource_uid VARCHAR(255) NOT NULL,     -- ResourceRecord::uid()
    resource_kind VARCHAR(50) NOT NULL,     -- container / image / pod / node ...
    display_name VARCHAR(255),
    asset_id BIGINT,                        -- 归档后的台账主键，未归档为 NULL
    status_snapshot VARCHAR(32),
    raw_state VARCHAR(64),
    parent_uid VARCHAR(255),
    attributes JSONB,
    first_seen_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    last_seen_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    created_by BIGINT, created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    deleted SMALLINT NOT NULL DEFAULT 0
);
CREATE UNIQUE INDEX IF NOT EXISTS uk_asset_ops_link_uid
    ON {schema}.asset_ops_link(connection_id, resource_uid);
CREATE INDEX IF NOT EXISTS idx_asset_ops_link_asset ON {schema}.asset_ops_link(asset_id);
CREATE INDEX IF NOT EXISTS idx_asset_ops_link_seen  ON {schema}.asset_ops_link(last_seen_at DESC);
```

唯一键是 `(connection_id, resource_uid)` 而非全局 `resource_uid`：两台 Docker 主机上的同名容器不会互相覆盖；
跨主机归并靠 `asset_id` 收敛。

### 2.3 与台账的关联口径

- **写**：`collect` 只 upsert `asset_ops_link`，**不写** `assets`。
- **读**：`list_links` 对 `{schema}.assets` 做 **LEFT JOIN** 取 `asset_no`，台账表零结构变更。
- **归档**：`bind_ops_link(linkId, assetId)` 把 `asset_id` 回填到 link 行；建档仍走既有资产流程。

### 2.4 采集幂等与“不误判下线”纪律（总方案 §2.3）

1. 快照内每条资源按 `(connection_id, resource_uid)` upsert：刷新 `display_name` / `status_snapshot` /
   `raw_state` / `parent_uid` / `attributes` / `last_seen_at`，保留 `first_seen_at`。
2. `snapshot.partial_errors` **非空**时，仅执行「新增 / 更新」，**绝不**把本次未出现的资源标记为下线。
3. `snapshot.partial_errors` 为空（完整采集）时，本次未出现的 link 行置 `status_snapshot='gone'`，
   `last_seen_at` 不动（保留最后出现时间，便于排查）。

## 4. 接口契约（命令名 = HTTP 路径 = service 函数，三方逐字对齐）

| # | Tauri 命令 | HTTP | service 函数 | 入参 | 出参 |
|---|---|---|---|---|---|
| 1 | `get_ops_providers` | `GET /api/ops/providers` | `provider_options` | — | `Vec<OpsProviderOption>` |
| 2 | `get_ops_connections` | `GET /api/ops/connections` | `list_connections` | — | `Vec<OpsConnectionView>` |
| 3 | `get_ops_connection` | `GET /api/ops/connections/{id}` | `get_connection` | id | `OpsConnectionView` |
| 4 | `create_ops_connection` | `POST /api/ops/connections` | `create_connection` | input + userId | `OpsConnectionView` |
| 5 | `update_ops_connection` | `PUT /api/ops/connections/{id}` | `update_connection` | id + input + userId | `OpsConnectionView` |
| 6 | `delete_ops_connection` | `DELETE /api/ops/connections/{id}` | `delete_connection` | id | `()` |
| 7 | `test_ops_connection_draft` | `POST /api/ops/connections/test` | `test_draft` | input（不落库） | `OpsHealthView` |
| 8 | `test_ops_connection` | `POST /api/ops/connections/{id}/test` | `test_connection` | id | `OpsHealthView` |
| 9 | `collect_ops_resources` | `POST /api/ops/connections/{id}/collect` | `collect_now` | id | `OpsCollectResult` |
| 10 | `get_ops_links` | `GET /api/ops/links` | `list_links` | connectionId? | `Vec<OpsResourceLinkView>` |
| 11 | `bind_ops_link` | `POST /api/ops/links/{linkId}/bind` | `bind_link` | linkId + assetId | `OpsResourceLinkView` |

`httpAdapter.extractParams()` 的既有规则：路径占位符从入参取出拼 URL，GET 剩余参数进 query string，
非 GET 剩余参数进 JSON body —— 因此 `bind_ops_link({ linkId, assetId })` 自然拆成 path + body。

### 5.1 `apps/web/src/services/opsService.ts`（S7）

### 5.2 `/ops/connections`（连接管理）

## 6. 安全与合规

1. **凭证加密**：`auth_config_enc` 用 `utils::crypto`（AES-256-GCM，密钥 `LLM_KEY_ENCRYPT_KEY`）。
   该变量当前**未配置**（`.env.toml` 只有 `[postgres]/[otel]/[api]/[auth]/[s3]/[snowflake]/[surrealdb]`），
   需在 `.env.toml` / `.env.example.toml` 增 `[llm] key_encrypt_key`（`load_env` 会映射成 `LLM_KEY_ENCRYPT_KEY`）。
2. **掩码**：`AuthKind::Debug`（已有）与 `OpsAuthPayload::Debug`（新增）均掩码；`OpsConnectionView` 不含任何 PEM / Token。
3. **临时证书**：目录名只含 pid/序号/纳秒；unix 目录 0700、文件 0600；`Drop` 删除；不写日志内容。
4. **只读纪律**（总方案 §6）：连接器只调 ping / version / list / get；本刀不引入 exec / start / stop / delete。
5. **风险提示**：`plain_tcp` 与 `insecure_skip_tls_verify=true` 在接口返回 `risk_hints`，前端红/黄警示。
6. **多租户**：两张表都建在租户 schema（`schema_prefix()`），凭证随租户隔离。

## 9. 风险与待决事项

| # | 事项 | 说明 / 决策 | 影响 |
|---|---|---|---|
| 1 | k8s-openapi 版本 | 必须升到 0.28.0（kube 4.2 硬要求）；0.28 支持 v1_32~v1_36 | 不升则 `--features k8s` 永远编不过 |
